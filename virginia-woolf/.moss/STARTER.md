# Intro

The simplest moss starter: a single-author site in the author's own voice — essays, one talk (with prev/next chapters), an about page, and a bibliography. This copy is filled in with Virginia Woolf's own public-domain writing (*The Common Reader*, First Series, 1925, and *A Room of One's Own*, 1929) so the starter ships with real, readable content instead of lorem ipsum. `notes/essays-brief.md` in the parent repo records who she is here and why the pages are shaped the way they are.

This file lives at `.moss/STARTER.md`, not the site root, and is named `STARTER`, not `README` — both on purpose, and both corrections of an earlier, wrong assumption. `draft: true` does **not** keep a page out of the build: it only hides a page from listings/nav/sitemap and marks it `noindex` — the page is still built and served at its own URL. A root-level `README.md` with `draft: true` was checked against a real build and did in fact render at `/starter/`, `noindex` but reachable; the only way to keep this file out of the build entirely is to put it somewhere moss does not scan for content at all, which is `.moss/`. Filename matters separately: moss's self-named-home check runs on raw filenames before frontmatter is read, and `readme` is one of its reserved index stems (alongside `index`, `_index`, `main`) — a root `README.md`, `draft` or not, would still contest the home slot with `Virginia Woolf.md`. See "moss feedback" in `notes/essays-brief.md` for both bugs this exposed. **`Virginia Woolf.md`'s `home: true` must stay** — checked by removing it and rebuilding: the root page stopped being her name page at all and became moss's generic fallback, a site-wide feed of every page grouped by year (Books, then each Talks chapter, then …), which is not this site's home page.

## Making it yours

Replace `Virginia Woolf.md`'s body with your own name, replace the essay and talk files with your own writing (keep the numbered-filename convention below), swap `assets/portrait.jpg` for your own photo, and update or delete the plain metadata list at the bottom of `About.md` (it names Woolf's own books, editions, and public-domain status specifically, not anything generic — see "Books folded into About" below; there is no separate `Books.md` any more). `.moss/templates/essay.md` and `.moss/templates/talk.md` are plain frontmatter skeletons to copy from — moss's own template picker isn't released yet, so these are copy-me files, not a wired-up feature.

## Numbered filenames

Essay and chapter files are named `01-`, `02-`, … because a folder's default listing order follows the filename, not the title or an added `weight`. Numbering the files gets correct book order for free; the alternative (a `weight` frontmatter key) would have added a fourth content key beyond `title`/`date`/`description`.

**Correction, 2026-10-01, after adding a Talks chapter with an earlier date:** the claim above only holds while every file in the folder shares one `date`. Adding `Talks/00-how-should-one-read-a-book.md` (occasion date 1926-01-30, filename sorts first of all seven) made it render *last* in the Talks listing, after all six `1929-10-24` chapters in their `01`–`06` order — so the real default, with no `sort:` key set, is `date` descending with filename only breaking ties within one date, not filename order outright. `Essays/Essays.md` was already carrying an explicit `sort: weight` for exactly this reason (see `f7126c5`); `Talks/Talks.md` has none, and now needs one too if chapter order should ever survive a page with a different date landing in the same folder.

## The moss-specific frontmatter lines

Every content page here is plain markdown with only `title`, `date`, and `description` in frontmatter, except `Talks/Talks.md`, which also carries `series: true`. Without it, prev/next between chapters do not appear even though the chapters already sort correctly by their numbered filenames — `series` is a real opt-in, not automatic. `notes/essays-brief.md` (parent repo) has the full note, offered back to moss as feedback: a filename-ordered folder should default to `series: on`.

The nav order (originally Essays, Talks, Books, About; now Essays, Talks, Fiction, About — see "Books folded into About" below) needed a second necessary key: `weight` on `Essays/Essays.md`, `Talks/Talks.md`, `Fiction/Fiction.md`, and `About.md`. Without it, nav falls back to alphabetical, which is not the order asked for; `weight`'s own description ("sort weight for ordering") turned out to apply to the nav bar as well as folder-listing order — checked with a throwaway three-page scratch site before touching the real one.

## Site wiring (not a content-voice exception)

Getting the nav row into the top of the page — the layout the brief asked for — needed a few whole-site keys beyond the content rule above: `home: true` on `Virginia Woolf.md` (a root page only matches moss's folder-home convention automatically when its filename matches the folder, which the root has no name to match), `children: false` on the same file (so the home page shows only the name, not every page on the site as cards beneath it), `nav: true` on `Essays/Essays.md`, `Talks/Talks.md`, and `Fiction/Fiction.md` (folders are not in nav by default), and `weight` as above. These are routing, not prose — no sentence of hers or ours changes because of them — and the sibling `bada-shanren` starter in this same repo already uses the identical `home`/`nav`/`series` set for the same reasons.

## No footer (provenance lives on About.md now)

There is no `footer.md`. An authored colophon footer was tried for two rounds (a root-level `footer.md` is a recognized moss slot, injected into every page's `<footer>` automatically and never built as its own page — `crates/moss-build/src/build/footer.rs`) and then removed on user review: it made the name-only home page lose its cleanness, and its own link index just repeated the top nav. The "no footer" route (as frankchimero.com takes it) reads better for a starter this small.

Every page's `<footer class="container">` used to render empty — no authored content, no auto-generated link row (that only appears with `footer: true` pages or a live RSS link, and this starter has neither) — followed by moss's own small site-colophon mark (the leaf icon linking to mosspub.com), which is separate chrome outside `<footer>` entirely, not something this starter controls or should try to suppress. Since `[site] header = "nav"` (below), moss no longer emits the `<footer>` element at all, empty or not — confirmed by grepping a real build's output for `<footer` and finding nothing on any page — so this starter has neither a footer nor its divider now, not just an empty one.

## Header mode: `[site] header = "nav"`

`.moss/config.toml` sets `[site] header = "nav"`. In this mode the header shows no site name on any page (the `.site-name` class only remains in moss's own bundled CSS/JS, never in any page's HTML) and opens with a `Home` link — `<a href="/" class="active" aria-current="page">Home</a>` on the home page itself, plain `<a href="/">Home</a>` elsewhere — followed by Essays, Talks, Fiction, About, all left-aligned with the theme toggle at the right. Checked at both 1280 and 390: all five items sit on one line at either width, since there is no site-name text competing for space any more. `Virginia Woolf.md`'s hand-written `# Virginia Woolf` heading stays exactly as it was (deliberately -- the name lives as an editable line in a file, not a config value or a nav-brand string).

Provenance — her own bibliography, the two editions (publisher, year), the public-domain statement, and the typefaces — lives on `About.md`, as a plain list below her own words and the portrait: metadata, not prose, same as the dateline's own reasoning (see below). The RSS-link investigation from the footer.md era (moss appends its own feed link unconditionally once `show_rss_in_footer` is true, itself gated by `[site] rss_footer` in `.moss/config.toml`, default `false`, checked empirically to *not* also require a deployed URL) has no footer left to apply to, but the finding stands if a future footer or nav feed link is ever added: don't set `rss_footer = true` in this starter's own config, since it shows the link on a bare undeployed build too.

## Type and colour (this round's redesign)

Display: **Fraunces**, instanced at its largest optical-size cut (`opsz=144`, weight 400) with `fonttools varLib.instancer` from the variable font, not shipped as a variable file — a single static cut is smaller and this starter only ever uses one size context (the home name / page titles) for it. Body: **Literata** at its text optical size (`opsz=12`, its own default), instanced the same way at weights 400/400-italic/700. Both SIL OFL, both self-hosted in `.moss/theme/fonts/`; all four files together are 88 KB (well under a 200 KB budget) because instancing keeps only the one axis-position actually used, not the whole variable font. Body size is a fluid Utopia-style `clamp()` — 19px at a 320px viewport to 21px at 1280px — documented with its own min/max/ratio in the CSS comment; the measure itself is NOT fluid (still ~65-67ch, moss's own default multiple of reading-size, per research principle "a fixed measure never goes fluid").

Colour: one hue (150°, sage — Bloomsbury's own palette, not hazelweakly.me's rose), one saturation (20%), light/dark inverting the same two lightness stops as before, just moved off 340°/35%/93%/13%. Computed contrast (not eyeballed, see the CSS comment): body text 13.13:1 in both modes (target 7:1); accent needs its own light (36%, 5.07:1) and dark (62%, 6.28:1) lightness, since no single lightness clears 4.5:1 against both a 94%-L and a 14%-L page.

## The dateline (this round's signature detail)

Every essay and talk chapter opens with a one-line dateline — her first-publication venue and date, e.g. `_Times Literary Supplement, 10 April 1919._` or `_The Common Reader, 1925._` — written as plain markdown (a single emphasised sentence, the file's first paragraph) and styled in CSS, not templated as a frontmatter field, because it is still her publishing history rendered as a line of text, not metadata the schema has a slot for. Sourced entirely from `moss-commons/collections/woolf-essays/structure.md`, and only as precisely as that file itself commits to: a day is stated only where `structure.md` marks it `[confirmed]` with an exact date quoted from a primary or directly-cited source (e.g. Modern Fiction's 10 April 1919); a `[corroborated]` entry with year-only agreement gets a bare year (Montaigne: "Times Literary Supplement, 1924", no day); one essay (How It Strikes a Contemporary) gets a bare year with no venue at all, because `structure.md` flags its assumed TLS venue as never independently confirmed. The six Talks chapters all carry the same combined dateline, both lecture venues and dates together, because `structure.md` is explicit that the book is not a clean per-chapter split of the two 1928 papers — asserting one venue per chapter would have been a guess the source itself rules out.

CSS matches `article.container p:first-of-type:has(> em:only-child)` — the first `<p>` sibling that contains nothing but an `<em>` — and restyles it as a periodical masthead line (Fraunces, small caps, `font-style: normal` overriding the italic slant, letter-spaced, muted) rather than leaving it as body-text italics. The selector only matches because every dateline is written as one bare emphasised sentence and nothing else on any page takes that exact shape.

## moss feedback from this pass (2026-10-01, updated third pass against moss develop `d1218ae06`)

Building the two new dated events against real moss surfaced three separate gaps, recorded here rather than worked around with CSS or extra frontmatter keys, per this round's brief; a fourth, about the places/map rendering, came out of the same gazetteer work. All four are now fixed upstream, in moss develop `d1218ae06` (2026-10-01, unreleased) — the installed 0.15.3 app this starter was first built against still has every bug described below.

**`.moss/places.toml` `precision` silently downgraded an unrecognised value instead of rejecting it.** The research brief for this site asked for `precision = "town"` for both new gazetteer rows (St Ives, Hayes Court); moss's actual enum is `exact`/`city`/`region`/`country`, so `"town"` was invalid — but the build only warned ("has an invalid precision 'town'; treating it as 'country'") and kept going, silently falling all the way to the *least* precise option rather than, say, the nearest valid one or an error. Both rows still use `precision = "city"` (matching the existing small-town rows like Haworth); `"town"` was never a real option, so this is the correct value, not a workaround for the bug. **Fixed:** an unrecognised precision now raises a diagnostic naming the allowed values, instead of guessing one.

**A folder's default listing order is not filename order once dates differ, `sort:`'s named axes had no ascending direction, and its documented explicit-order escape hatch silently stopped working once the subfolder it named had children of its own.** Adding `Talks/00-how-should-one-read-a-book.md` with an earlier date pushed it to the *end* of the Talks listing, after all six later-dated chapters (see the dated correction under "Numbered filenames" above). Wanting Talks read oldest-first (Bennett 1924, then How Should One Read a Book 1926, then A Room of One's Own 1928) ran into two limits at once: `sort: date` offered only one direction (newest-first, same as no `sort:` key at all), and the documented explicit-order form (`sort: [mr-bennett-and-mrs-brown, "00-how-should-one-read-a-book", "A Room of One's Own"]`) worked exactly as documented in an isolated three-page scratch site but silently did nothing once reproduced against the real site — bisected to the one subfolder entry in the list holding children of its own: the explicit order held with zero nested children and broke the moment the subfolder held even one, in both `A Room of One's Own/` (six chapters) and a plain scratch repro, so this wasn't particular to this site's content. Landed on `sort: date` and left the chronology ungamed rather than depend on a broken feature. **Fixed, both:** `sort: date-asc` now exists, and `Talks/Talks.md` uses it — the three occasions list oldest-first with no explicit-order trick needed; separately, the explicit `sort: [a, b, c]` list itself now matches subfolders with children of their own, instead of silently no-opping.

**The `/places/` page, and any page whose frontmatter lists more than one place, rendered no map at all.** `[terms.places]` (`type = "place"`, `fields = ["location"]`) already turned a bare `location:` name into a Location: line, and `[site] locator = "align-right"` already drew a small map beside a single place — but the `/places/` index generated from the nine rows in `.moss/places.toml` was a bare list with no markers, and a page citing several places at once got no map of its own. **Fixed:** the `/places/` page now draws every place with an interactive explorer map on by default; a page with a list of places gets a map of its own too; `explorer = false` under `[terms.places]` turns the explorer off for whoever wants the plain list back.

## Fiction shelf added, a deliberate scope change (2026-10-01)

`Fiction/` is a fourth shelf (`nav: true`, `weight: 3`, `sort: date-asc`, between Talks and Books — Books has since folded into About, see "Books folded into About" below; `About.md` moved to `weight: 5` to make room), carrying six chapters lifted whole out of five of Woolf's own novels and story collections rather than her essays and talks: Kew Gardens (from *Monday or Tuesday*, 1921), two chapters of *Jacob's Room* (1922) — one set in Paris, one in Greece — the Constantinople chapter of *Orlando* (1928), the Lisbon chapter of *The Voyage Out* (1915), and the Westminster opening of *Mrs Dalloway* (1925). This is a real change to what the site claims to be: until now every word on it was non-fiction, essays and lectures in her own hand about real places and real reading. A chapter of a novel is invented narrative; the place named in it is real only because Woolf is independently documented to have been there herself, not because the scene is reportage. Each chapter was checked against that bar before it went in — the name had to appear in the extracted text (confirmed by `grep -c` against the cut file, not by re-reading it in full), and a biographical source for the visit had to exist independent of the novel — and that biographical source lives only in the page's `source:` frontmatter, never in the rendered body, per this site's standing rule that nothing in our own voice appears on a page. Two things the brief asked for turned out not to hold on closer reading and were corrected rather than forced: Jacob's Room's Greece chapter names Olympia, Athens, and the Acropolis, and Woolf's own 1906 diary and letters confirm that itinerary (Patras–Olympia–Athens–the Acropolis) in detail; the second Greece visit the research brief cited for 1910 turned out on checking to be a Constantinople-only emergency trip to nurse Vanessa, with no Greek leg, so the Greece chapter's source cites only 1906, while Orlando's Constantinople chapter correctly cites both 1906 and 1910.

`location:` is doing double duty on these six pages, same key, different meaning than everywhere else on the site. On every essay and talk, `location:` names a place the piece is about or set in, in her own non-fiction voice. On a Fiction page it names the chapter's *fictional setting* — anchored to a real, visited place, but still a setting inside invented narrative, not a report of a journey she took. That distinction is real and the schema does not currently carry it; the brief anticipated this ("the key will be switched from `location:` to a dedicated one later") and `location:` was used as directed, as a placeholder, not a fix. All eight new places this shelf needed — Kew Gardens, Westminster, Paris, Lisbon, Olympia, Athens, Acropolis, Constantinople — went into `.moss/places.toml` with Wikidata-sourced coordinates regardless, since the map has no notion of "setting" versus "visited" either and a place pin is a place pin until that second axis exists. The `/places/` map went from 9 marked places in 3 countries (England, France, Spain) to 17 in 6 (adding Portugal, Greece, Turkey) — genuinely Europe-scale now, checked in a real build and screenshotted, not just counted in the TOML file.

Two Jacob's Room chapters share one `date:` (1922-10-26, the book's publication date — neither chapter has an independently recorded composition date), which collide under `sort: date-asc` exactly the way the Talks restructuring already found dates could: the fix there was a `sort:` axis, the fix here was simpler because there are only two pages, not a whole series — the Paris chapter is filed as `jacobs-room-paris.md` and the Greece chapter as `jacobs-room-the-acropolis.md`, and `paris` sorts alphabetically before `the-acropolis`, so the same-date tie-break (confirmed in STARTER.md's own notes above to fall back to filename) lands them in the book's own order without needing a third `sort` value. ## Titles, dates and Essays order (2026-10-02)

Titles follow the source edition's own printing. For The Common Reader the book prints "The Lives of the Obscure" and "Outlines" as group titles with numbered parts, so the seven part pages read `The Lives of the Obscure: I. The Taylors and the Edgeworths` and `Outlines: I. Miss Mitford`, one convention for both groups (group title with its article, colon, numeral and part name as the contents page prints them). "Mr. Bennett and Mrs. Brown" keeps its periods, as the 1924 Hogarth pamphlet prints them. "A Walk at Night" is the Guardian title as S. P. Rosenbaum gives it (Virginia Woolf Miscellany no. 26, 1986); "A Walk by Night" is the Collected Essays title, recorded in `source:`. The Guardian page itself was not seen, so this rests on one editor's word. The Gutenberg e-text of Mrs Dalloway heads itself "Mrs. Dalloway (1925)", so the Fiction title uses the period.

The six chapters of A Room of One's Own have no printed titles, only numerals. One rule makes them: the opening words up to the first comma, dash or full stop that leaves at least three words, verbatim, without the mark. `description:` continues from where the title stops.

Dates carry the precision the evidence supports. A full day means the day is verified (a periodical scan or a scholarly citation). A day marked in `source:` with "The day follows the standard bibliography and was not checked against the issue" is a deliberate educated guess, the guess marker for this site. A month (`1925-03`) means only the month is known. Where the essay was written for the book, or the book text is substantially new, `date:` is the book's 1925-04-23 and `source:` names any earlier piece. Tally of the 30 Essays: 10 verified day, 6 guessed day, 5 month, 9 book date.

`Essays/Essays.md` is `sort: date-asc`, so the shelf reads in order of first publication and each card shows its date (year and month). Pages sharing a date keep their numbered-filename order, which is book order.

## Where maps show

Maps appear only on the four journey essays (Haworth, A Walk at Night, To Spain, Street Haunting), one per article, and nowhere else: not on folder pages, and there is no "Location: …" text line. Three switches do this. `[terms.places] line = false` in `.moss/config.toml` removes the automatic place line from every page, while `location:` still feeds the place beside the date on listing cards and the `/places/` root. `[site] locator` is left at its default, `none`, so no page gets a map by itself. `map: true` in a page's frontmatter shows that page's locator map; `map: false` hides it. To Spain keeps `route: true`, which draws its route on the map. To add a map to another essay, give it `location:` and `map: true`.
